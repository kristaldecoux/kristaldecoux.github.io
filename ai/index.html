AI tools that take the busywork off my team’s plate

I’ve made AI part of how my team works. These Claude skills handle the repetitive parts of web operations, so people spend their time on judgment, not copying and formatting. I also used Claude to build this website.

Tools

For content authors

SEO review

Writers run it on draft web copy in their own Claude before a page goes live, so search and AI-readiness are built in rather than bolted on afterward.

You give it

  • Draft copy for a web page

You get back

  • A meta title and description
  • Structured data (schema) for the page
  • Prioritized keyword and copy recommendations for readability by people, crawlers and AI models

Our content is showing up more often in AI answers and overviews.

For the optimization team

Optimization brief

Test and merchandising requests arrive in emails, Slack threads, tickets and meeting notes. This skill turns any of them into everything needed to launch.

You give it

  • An A/B test or web merchandising request, in any format
  • Any scoping data you have, like traffic and baseline conversion

You get back

  • An experiment brief for the testing platform
  • A test plan document with a unique test ID used everywhere
  • A tracking issue in GitHub
  • A targeting recommendation and metric names that follow our conventions
  • A review email for the team
  • For merchandising, copy formatted to the placement’s character limits and an editorial calendar entry

One request in, every launch document out, with nothing missed and every name consistent.

For the web team

Request triage

Built when marketing’s requests lived in Workfront and the web team worked in GitHub. It reads a request, works out what’s needed and what’s missing, and does the follow-up. Read the case study.

You give it

  • A request ticket from marketing

You get back

  • A request type, a complexity rating and routing to UX, SEO, localization or design
  • A labeled GitHub issue for the web team
  • An email to the requester with a checklist of missing details

Triage went from 30–60 minutes per request to seconds.

Open-source skills anyone can use

I rewrote my testing and web playbooks as seven Claude skills that work for any team, and published them on GitHub under an open-source license. The statistics run in a small script, so the numbers are calculated, not estimated.

SkillWhat it does
A/B test readoutTurns visitor and funnel counts into significance, confidence intervals, a sample ratio check and a decision-ready readout.
Test sizing and prioritizationWorks out how many visitors a test needs and how long it will run, and ranks ideas with RICE scores.
“Has this been tested?”Searches a test archive for similar past tests and advises whether an idea is worth revisiting.
Project brief reviewerScores a web project request, rewrites vague answers, proposes an effort tier and drafts a reply to the requester.
Launch page updaterMaps a launch, report or event to the page sections that need updating, with draft copy and an SEO checklist.
Optimization briefTurns a test or personalization request into a tracking issue, platform brief, test plan and review email, set up once for any team’s tools.
SEO reviewReturns a meta title and description, schema and prioritized fixes for search engines and AI assistants.

Case study

This website: a job-search site built with AI in two days

I started with one portfolio page and a resume. Two days later I had a nine-page site with a brand system, five case studies, a testing portfolio checked against my original test files, analytics, and pages ready for AI tools to read. Claude did the heavy lifting; I set the direction and decided what was true.

Where I led

  • Strategy and brand. I defined the positioning, audiences, information architecture and voice, then workshopped several palettes and font pairings, each checked for accessibility, before choosing the one that best represents my work.
  • The facts. Claude read my archive of past test plans and results in Google Drive, more than a hundred decks and workbooks. Every result on the site was checked against those source files.
  • Test, then share. I opened the site to search engines and AI crawlers and measured how well it performed before choosing to share it by direct link.

What we built

  1. Brand and content

    A brand guide, then the pages

    A written brand guide covering positioning, message pillars, voice, information architecture and an accessible color palette. Then the homepage, case studies, experiments, method, AI tools, search strategy, about, contact and privacy pages, and a matching resume PDF.

  2. Publishing

    GitHub to Vercel

    The site lives in a GitHub repository and deploys automatically to Vercel, with cookieless analytics so I can see which pages recruiters read.

  3. Search and AI readiness

    Built to be read by machines too

    SEO titles and descriptions written to the rules of my own SEO review skill, structured data describing who I am, an llms.txt summary, and Markdown versions of every page served to AI tools that ask for them.

    In testing, Lighthouse SEO rose from 60 to 100, with accessibility and best practices at 100, and an agent-readiness audit rose from 65 to 98.

How I approach AI at work

  • Start with the repetitive work. Copying tickets, formatting briefs and writing metadata are where AI saves the most time with the least risk.
  • Keep people in charge of judgment. Every tool produces a draft that a person reviews before it goes anywhere.
  • Build it into the way people already work. Each skill runs in the tools the team already uses and follows our existing conventions.
  • Share it. Skills are written so anyone on the team can install and use them, with a guide for each.
